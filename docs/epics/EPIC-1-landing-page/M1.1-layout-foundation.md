# M1.1: Layout foundation

## Goal
Create the shared landing/layout foundation: header/nav, footer, Arabic/English switch, and RTL/LTR direction handling.

## In scope / Out of scope
- **In scope:** Basic header with nav links, footer, language toggle, RTL/LTR handling following existing i18n architecture.
- **Out of scope:** Real design polish, animations, imagery, auth logic, templates.

## Tasks
1. Inspect relevant existing layout patterns (if present) in `src/app` or shared components.
2. Implement landing layout skeleton (server/client split as needed per patterns).
3. Add language switcher with route preservation.
4. Add AR/EN translation keys for labels used.
5. Ensure RTL/LTR works correctly with logical properties.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M1.1-01 | Landing page has a header with navigation | View in browser (EN and AR) |
| M1.1-02 | Language switch toggles between EN/AR and preserves route | Navigate then switch; route context preserved |
| M1.1-03 | HTML dir is `rtl` for AR, `ltr` for EN | Inspect HTML `dir` attribute in both locales |
| M1.1-04 | Layout uses logical properties (no layout-critical `left/right/ml/mr/pl/pr`) | Code inspection against CODE_RULES |
| M1.1-05 | Footer renders on landing page in both locales | Visual check |

## Definition of Done
- All AC pass, build passes (`npm run lint`, `npx tsc --noEmit`, `npm run build`).
- Reviewer reports no `CODE_RULES.md` violations.
- Status updated to `done` in `STATUS.md`.
