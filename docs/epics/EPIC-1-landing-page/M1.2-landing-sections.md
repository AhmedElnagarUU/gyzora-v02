# M1.2: Landing sections skeleton

## Goal
Add landing page sections as skeleton placeholders: hero, features/value, how it works, target industries, CTA.

## In scope / Out of scope
- **In scope:** Simple section blocks with headings/placeholder content clearly marked as sample if needed. Use `lucide-react` icons minimally.
- **Out of scope:** Real design polish, animations, imagery, template previews, pricing, auth.

## Tasks
1. Create section components following feature-based structure (per CODE_RULES).
2. Add AR/EN translation keys.
3. Compose landing page with sections.
4. Ensure sections are accessible (semantic HTML, headings hierarchy).

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M1.2-01 | Landing includes: hero, features/value, how it works, target industries, CTA | Visual inspection in EN/AR |
| M1.2-02 | No placeholder text that could be mistaken for real company claims (sample labels if used) | Content review |
| M1.2-03 | All user-facing text comes from i18n (no hardcoded strings) | Code inspection |
| M1.2-04 | RTL/LTR renders correctly for sections | Visual check in AR/EN |
| M1.2-05 | Sections use semantic HTML (`<section>`, `<h1>..`, etc.) | Inspect markup |

## Definition of Done
- All AC pass, build passes, Reviewer finds no CODE_RULES violations.
- Status updated in `STATUS.md`.
