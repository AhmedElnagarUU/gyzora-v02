# M2.1: Signup

## Goal
Implement signup using the existing authentication system with server-side validation, error states, and redirect after success.

## In scope / Out of scope
- **In scope:** Signup form, server-side validation, error states, success redirect. Use better-auth (approved). Implement via API route handlers (`src/app/api/**`) only; no Server Actions.
- **Out of scope:** Email verification, social login, roles.

## Tasks
1. Inspect existing auth implementation (delegate to sub-agent if needed) to follow exact patterns.
2. Install/configure better-auth if not present (approved dependency).
3. Add signup form/UI consistent with project structure (feature-based).
4. Implement server-side validation (zod) and call auth via API route handlers.
5. Handle errors without leaking sensitive info.
6. Redirect after successful signup.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M2.1-01 | Submitting valid signup creates an account via existing auth system | Manual test with sample data |
| M2.1-02 | Invalid data rejected with server-side validation errors shown | Test invalid email/password cases |
| M2.1-03 | Submitting signup with an existing email shows an error and creates no duplicate user | Test existing email |
| M2.1-04 | After success, user is redirected appropriately | Manual navigation check |
| M2.1-05 | No sensitive information leaked in error messages | Review error text |

## Definition of Done
- All AC pass, build passes, Reviewer finds no CODE_RULES violations.
- Status updated in `STATUS.md`.
