# M2.1: Signup

## Goal
Reimplement signup through the shared Better Auth client and verify account creation, cookie/session establishment, safe errors, and redirect.

## In scope / Out of scope
- **In scope:** Signup form, existing Zod validation, `authClient.signUp.email`, safe error states, success redirect, session establishment through Better Auth's catch-all API route.
- **Out of scope:** Email verification, social login, roles.

## Tasks
1. Complete M2.0 and verify the installed-version client API.
2. Use the shared `authClient.signUp.email` from the signup form; do not manually call an ad hoc endpoint.
3. Keep client-side feedback validation and Better Auth server validation; retain safe error messages.
4. Verify successful signup creates a database-backed account, establishes a session, and reaches the intended locale-aware route.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M2.1-01 | Submitting valid signup through Better Auth creates exactly one database-backed account | Manual test with sample data and database check |
| M2.1-02 | Invalid data rejected with server-side validation errors shown | Test invalid email/password cases |
| M2.1-03 | Submitting signup with an existing email shows an error and creates no duplicate user | Test existing email |
| M2.1-04 | After success, a usable Better Auth session exists and user is redirected to the intended locale-aware route | Browser check and server session check |
| M2.1-05 | No sensitive information leaked in error messages | Review error text |

## Definition of Done
- All AC pass, build passes, Reviewer finds no CODE_RULES violations.
- Status updated in `STATUS.md`.

## Verification record
- Browser signup in EN and AR created one user and an authenticated MongoDB session; the server-protected dashboard recognized both sessions.
- Duplicate email and a password exceeding Better Auth's server limit were rejected with generic translated feedback; duplicate/invalid users were not created.
- The runtime test users and their credential records were removed after verification.
