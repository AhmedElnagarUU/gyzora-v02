# M2.2: Sign in

## Goal
Implement sign in with invalid-credentials handling that doesn't leak sensitive info and creates session.

## In scope / Out of scope
- **In scope:** Sign in form, session creation, safe error handling. Use better-auth; API route handlers only (no Server Actions).
- **Out of scope:** Password reset, social login.

## Tasks
1. Implement sign in form under `src/features/auth/components/`.
2. Call existing auth system via API route handlers (`src/app/api/**`).
3. On invalid credentials, show generic safe error message.
4. Establish session and redirect on success.
5. Validate inputs server-side with zod.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M2.2-01 | Valid credentials sign in successfully and create session | Manual test |
| M2.2-02 | Invalid credentials show generic error (no user existence detail) | Test wrong email/wrong password |
| M2.2-03 | After success, authenticated user can access protected route | Manual navigation |
| M2.2-04 | Server validates credentials (not client-only) | Code inspection |
| M2.2-05 | Error messages do not leak sensitive info | Review text |

## Definition of Done
- All AC pass, build passes, Reviewer finds no CODE_RULES violations.
- Status updated in `STATUS.md`.
