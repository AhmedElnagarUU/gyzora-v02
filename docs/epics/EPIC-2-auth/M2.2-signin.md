# M2.2: Sign in

## Goal
Reimplement sign-in through the shared Better Auth client, verify session cookies, and provide generic invalid-credential handling.

## In scope / Out of scope
- **In scope:** Sign-in form, `authClient.signIn.email`, session creation, safe errors, locale-aware redirect.
- **Out of scope:** Password reset, social login.

## Tasks
1. Complete M2.0 and use the shared client from `src/features/auth/lib/auth-client.ts`.
2. Call `authClient.signIn.email` and handle the documented client result without assuming success from an HTTP status alone.
3. Show a generic error for invalid credentials, without exposing account existence.
4. Verify the resulting session using the server session helper and redirect to the intended locale-aware route.
5. Retain boundary validation as appropriate; Better Auth remains the authority for credential verification.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M2.2-01 | Valid credentials sign in and create a session accepted by the server session helper | Browser and server check |
| M2.2-02 | Invalid credentials show generic error (no user existence detail) | Test wrong email/wrong password |
| M2.2-03 | After success, authenticated user can access protected route | Manual navigation |
| M2.2-04 | Credential verification occurs through Better Auth server endpoints, not client-only logic | Code inspection |
| M2.2-05 | Error messages do not leak sensitive info | Review text |

## Definition of Done
- All AC pass, build passes, Reviewer finds no CODE_RULES violations.
- Status updated in `STATUS.md`.

## Verification record
- Valid credentials created sessions recognized by the server in EN and AR and reached the matching locale dashboard.
- An incorrect password returned generic feedback without exposing account details.
