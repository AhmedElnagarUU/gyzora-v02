# M2.3: Sign out and route protection

## Goal
Reimplement and verify sign-out through the Better Auth client, ensure session invalidation, and retain server-validated dashboard protection.

## In scope / Out of scope
- **In scope:** `authClient.signOut`, session invalidation, post-sign-out locale-aware navigation and refresh, server-side dashboard layout guard using a validated session.
- **Out of scope:** Roles, Site creation, dashboard content.

## Tasks
1. Complete M2.0 and use the shared client’s documented `authClient.signOut()` action; do not hand-roll the sign-out request.
2. Handle the Better Auth result explicitly: show failure feedback and do not navigate as if sign-out succeeded when it fails.
3. On confirmed success, navigate to the locale-appropriate public/sign-in route and refresh server-rendered state.
4. Keep the protected dashboard check server-side with the Better Auth session API and current request headers.
5. Verify that reusing the browser after sign-out cannot access a protected route.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M2.3-01 | Authenticated user can sign out through Better Auth and the operation reports success only when confirmed | Browser test |
| M2.3-02 | Unauthenticated user accessing `/dashboard` is redirected to sign in | Manual test (logged out) |
| M2.3-03 | Authenticated user can access `/dashboard` | Manual test (logged in) |
| M2.3-04 | Protection uses server-validated session (not client-only) | Code inspection |
| M2.3-05 | After sign-out success, Better Auth session is invalid and protected route redirects after navigation/refresh | Browser test and server session check |

## Definition of Done
- All AC pass, build passes, Reviewer finds no CODE_RULES violations.
- Status updated in `STATUS.md`.
