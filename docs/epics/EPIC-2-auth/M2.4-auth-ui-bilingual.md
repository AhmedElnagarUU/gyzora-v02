# M2.4: Auth UI states and bilingual

## Goal
Add bilingual AR/EN labels/messages and proper UI states (loading/success/error) for auth flows, with RTL layout support.

## In scope / Out of scope
- **In scope:** Loading/success/error states, AR/EN translations, RTL layout, consistent styling.
- **Out of scope:** Password reset, social login, email verification.

## Tasks
1. Add translation keys for auth labels/messages in EN and AR.
2. Update auth forms/pages to use i18n (no hardcoded strings).
3. Implement loading/success/error states with accessible feedback.
4. Ensure RTL/LTR correct using logical properties only.
5. Follow existing UI patterns and feature-based structure (components under `src/features/auth/components/`).
6. Auth forms and sign-out UI call the shared Better Auth client; the client communicates through the Better Auth catch-all endpoint. No Server Actions.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M2.4-01 | All auth UI strings come from i18n (EN and AR) | Code inspection + visual check |
| M2.4-02 | Forms show loading state during submission | Manual interaction |
| M2.4-03 | Error and success states reflect the actual Better Auth result; failures are never shown as success | Manual test (invalid + valid) |
| M2.4-04 | RTL layout correct in AR, LTR in EN | Visual check |
| M2.4-05 | Uses logical properties; no layout-critical directional CSS | Code inspection |

## Definition of Done
- All AC pass, build passes, Reviewer finds no CODE_RULES violations.
- Status updated in `STATUS.md`.

## Verification record
- EN and AR auth forms, validation/errors, dashboard labels, and locale-specific redirects were exercised; Arabic route layout reports `dir="rtl"`.
- Signup displayed its disabled loading label during submission; signout loading and both locales' signout failure feedback were also observed.
- Auth success/error text is translated, generic, and based on Better Auth results; no direction-specific layout styles were added.
