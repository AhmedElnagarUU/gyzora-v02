# M3.1: Dashboard and route guard

## Goal
Add the authenticated dashboard shell and server-validated route protections that show Site status and links to editor, preview, and publish.

## In scope / Out of scope
- **In scope:** dashboard layout, conditional Site state, route guard, navigation to editor and publish actions
- **Out of scope:** project management, public-site rendering, payment flows

## Tasks
1. Inspect the current auth/session wiring and dashboard route patterns.
2. Implement protected dashboard route that relies on server-side session validation.
3. Show empty-state if no Site exists and active-state if Site exists.
4. Add a safe redirect and error handling for blocked access.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M3.1-01 | Unauthenticated users are redirected away from the dashboard | Manual browser check |
| M3.1-02 | Authenticated users without any Site see a create-site CTA | Manual browser check |
| M3.1-03 | Authenticated users with a Site see the correct publish and editor actions | Manual browser check |
| M3.1-04 | Route protection is enforced on the server and not only in the client | Route test / code review |

## Definition of Done
- Dashboard loads correctly in EN and AR, with correct RTL/LTR handling.
- No auth bypass or client-side-only enforcement remains.
- Status updated in `STATUS.md`.
