# M3.2: Site creation flow

## Goal
Create a validated Site setup flow that captures the required profile information and initializes editable content from a chosen template without publishing.

## In scope / Out of scope
- **In scope:** Site creation form, server validation, template selection, default content generation, draft initialization
- **Out of scope:** publishing, custom domains, analytics

## Tasks
1. Define Site creation form payload and validation schema.
2. Populate the picker from the five supported template IDs provided by the template catalog; reject any unsupported ID server-side.
3. Implement server-side handler to create one Site per owner.
4. Initialize the Site draft using the selected template and user-provided company info without mutating the shared definition.
5. Return clear errors when required fields are missing or invalid.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M3.2-01 | Valid Site creation succeeds and initializes a draft Site | Manual form submission |
| M3.2-02 | Missing/invalid required fields are rejected with validation feedback | Form validation test |
| M3.2-03 | Selected template content is loaded into the editable Site without publishing | Browser check after creation |
| M3.2-04 | User input is stored separately from shared template content | Code review and DB check |

## Definition of Done
- Creation is valid in both languages and respects the PRD template constraints.
- The created Site can be opened in the editor immediately after creation.
- Status updated in `STATUS.md`.

## Progress and verification

- Added a feature-owned Site document type with separate, explicitly localized user profile values and a template reference.
- Added MongoDB repository functions to insert a Site and look one up by its authenticated owner's ID. No unique owner index or concurrent-create handling was added; those belong to M3.3.
- The five template designs and provisional IDs are specified in `docs/template-design/README.md`; the catalog now exposes those IDs and the shared renderer in `src/features/templates/`.
- The creation form and API handler are still not implemented, so Site creation cannot yet validate and persist a selected template. The database-backed insert and auth flow are also runtime-unverified because EPIC-2 records MongoDB Atlas DNS `querySrv ETIMEOUT`.
