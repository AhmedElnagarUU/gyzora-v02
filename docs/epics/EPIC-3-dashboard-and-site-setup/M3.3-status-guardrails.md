# M3.3: Duplicate protection and status handling

## Goal
Prevent duplicate Site creation under concurrency and make dashboard status handling safe, explicit, and testable.

## In scope / Out of scope
- **In scope:** unique index enforcement, safe creation logic, duplicate UI rejection, publish-status states
- **Out of scope:** project or site content editing

## Tasks
1. Add database uniqueness constraints for `Site.ownerUserId`.
2. Implement safe create logic that handles concurrent requests without partial state.
3. Add duplicate-creation guardrails in API and UI.
4. Expose draft/published states in dashboard logic without leaking data.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M3.3-01 | A second Site creation attempt is rejected with a clear error | Manual and API test |
| M3.3-02 | Two concurrent requests still produce at most one Site | Load-test or concurrent request simulation |
| M3.3-03 | Dashboard status accurately reflects publish and draft states | Manual verification |
| M3.3-04 | Ownership checks reject cross-user access attempts | API security tests |

## Definition of Done
- Duplicate creation is blocked safely in all paths.
- Concurrency tests pass and no critical isolation bug remains.
- Status updated in `STATUS.md`.
