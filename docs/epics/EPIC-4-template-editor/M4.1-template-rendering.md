# M4.1: Template schema and rendering

## Goal
Complete and verify five selectable Gyzora template variations as shared, structured definitions using the template-engine contract. The design brief specifies their visual identity and page/section structure.

## In scope / Out of scope
- **In scope:** five template definitions/catalog entries matching `docs/template-design/README.md`, integration with the engine, section layout, fallback handling, responsive rendering
- **Out of scope:** live project galleries or publishing logic
- **Engine dependency:** The initial catalog and renderer contract are implemented in `src/features/templates/`. This milestone completes template-specific verification and integration without introducing a competing renderer.

## Tasks
1. Use the five design briefs and stable IDs in `docs/template-design/README.md`; do not assume pre-existing template definitions.
2. Map each brief to the engine's supported pages, section types, field keys, and fallbacks.
3. Use the shared engine to render Home, About, Services, Projects, Project Details, and Contact equivalents.
4. Keep any demo content clearly labeled as sample and handle optional content and media gracefully.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M4.1-01 | All five templates render their agreed page structures in mobile and desktop layouts | Responsive browser check |
| M4.1-02 | Optional content and images do not break the layout | Browser validation |
| M4.1-03 | Placeholder or false claims are not present in template sample content | Manual design review |
| M4.1-04 | Five stable template IDs resolve through the engine and template content remains separate from customer data | Catalog, code review, and data validation |

## Definition of Done
- All five templates match the approved design brief, integrate with the engine, and render cleanly in EN and AR.
- Status updated in `STATUS.md`.
