# M4.3: Bilingual content model and fallbacks

## Goal
Ensure the site and editor support AR/EN content correctly, preserve route context, and handle missing translations without overwriting user text.

## In scope / Out of scope
- **In scope:** AR/EN toggles, RTL/LTR handling, explicit language fields, fallback policy, validation messages
- **Out of scope:** multi-language translation automation or new i18n infrastructure

## Tasks
1. Model language fields explicitly and ensure content is not inferred from direction.
2. Implement language switching that preserves Site context and route state.
3. Define fallback behavior for missing translations and required validation strings.
4. Validate that switching languages never overwrites customer text.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M4.3-01 | Switching language keeps the same Site and route context | Manual browser test |
| M4.3-02 | Editing in one language does not overwrite the other language field set | Data and UI test |
| M4.3-03 | Missing translation falls back cleanly without breaking the page | Manual validation |
| M4.3-04 | Layout remains correct in LTR and RTL, and labels are translated | Browser QA |

## Definition of Done
- EN and AR flows pass review, including correct directionality and safe fallback behavior.
- Status updated in `STATUS.md`.
