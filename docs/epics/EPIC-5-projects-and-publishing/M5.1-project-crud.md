# M5.1: Project CRUD and validation

## Goal
Allow customers to create, edit, and delete portfolio projects scoped to their own Site with validation that prevents malformed content from breaking the public pages.

## In scope / Out of scope
- **In scope:** project list, add/edit/delete, metadata, image validation, ownership checks
- **Out of scope:** billing, analytics, advanced filtering

## Tasks
1. Define project schema and validation rules for required and optional fields.
2. Implement server-side project CRUD under the current Site ownership model.
3. Enforce `siteId` scoping and deny cross-Site access.
4. Ensure delete and update handlers reject invalid ownership.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M5.1-01 | Users can add, edit, and delete projects attached to their own Site | Manual UI verification |
| M5.1-02 | Project validation rejects invalid titles, descriptions, or image payloads | API validation test |
| M5.1-03 | Cross-Site project access is denied | Ownership test |
| M5.1-04 | Project delete is scoped to the Site owner and not trusting client input | Security review |

## Definition of Done
- Project CRUD behaves correctly and is isolated to the owning Site.
- Status updated in `STATUS.md`.
