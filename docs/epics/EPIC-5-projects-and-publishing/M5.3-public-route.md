# M5.3: Public route and publish safety

## Goal
Ensure the public site route renders only the last successfully published content for the correct Site and handles unpublished or missing Sites gracefully without cross-tenant leaks.

## In scope / Out of scope
- **In scope:** stable public route, published content rendering, tenant isolation, graceful error handling
- **Out of scope:** custom domains and alternate routing schemes

## Tasks
1. Implement stable public route rendering under the existing routing model.
2. Verify only the last successful published version is served.
3. Return safe fallback states for unpublished, missing, or deleted Sites.
4. Confirm no tenant cross-rendering occurs in production-like checks.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M5.3-01 | The public route renders the correct Site only after a successful publish | Browser and API verification |
| M5.3-02 | Unpublished or missing Sites do not display invalid data | Manual route check |
| M5.3-03 | User A cannot render user B's published Site | Security test |
| M5.3-04 | Route remains stable under the existing routing architecture | Review and QA |

## Definition of Done
- Public site route is tenant-isolated, correct, and safe under failure conditions.
- Status updated in `STATUS.md`.
