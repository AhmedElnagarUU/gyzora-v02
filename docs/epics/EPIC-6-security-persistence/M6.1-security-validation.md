# M6.1: Security and validation hardening

## Goal
Harden all authenticated and owner-scoped operations with server-side session validation, safe authorization checks, and explicit protection against common input and data issues.

## In scope / Out of scope
- **In scope:** session validation, ownership-aware queries, input validation, secrets handling, basic rate limiting and error sanitization
- **Out of scope:** advanced bot protection or enterprise security tooling

## Tasks
1. Audit every protected route for server-side validation and ownership checks.
2. Remove any trust in client-supplied user IDs or site IDs.
3. Validate request payloads and sanitize error messages.
4. Confirm secrets are stored in environment variables and not in source control.

## Acceptance criteria
| AC | Testable binary statement | Verification method |
|---|---|---|
| M6.1-01 | Protected create/edit/delete/publish routes verify session on the server | Security test review |
| M6.1-02 | Ownership errors return safe responses and do not leak data | API negative testing |
| M6.1-03 | Validation rejects malformed payloads before database mutation | Route tests |
| M6.1-04 | Secrets are configured via environment handling and documented | Environment review |

## Definition of Done
- Protected operations are secure and safe under ownership and validation checks.
- Status updated in `STATUS.md`.
